في Quranic Terminology Lint فحصان. الأول يراجع البيانات التي يحفظها مشروعك أو ينشرها لغيره، مثل ملفات JSON وCSV وردود الـ API، ويخبرك بما سيقرؤه غيرك خطأ. والثاني يراجع أسماء المصطلحات في الكود، ويقترح الاسم الذي اتفقنا عليه. والمعيار والسجلات موجودة داخل الأداة نفسها، لذلك تعمل على جهازك بعد التثبيت، من غير إنترنت.

لنفترض أن تطبيقك يصدّر توقيتات آيات سورة البقرة في ملف `exports/al-baqarah.json`:

```json
{
  "surah": 2,
  "ayahs": [
    { "ayah": 1, "start_ms": 0, "end_ms": 4037 },
    { "ayah": 2, "start_ms": 4037, "end_ms": 8111 },
    …
  ]
}
```

في الملف ٢٨٥ آية. عند الـ commit، يمرّ الـ commit، لكن فحص البيانات يعرض هذا التحذير:

```text
Meaning — what a consumer would read wrongly
  ! warning  ayah numbers that are not Kufi, and nothing says so: rule 072 reads unstated numbers as
             Kufi, so a consumer would pair them with the wrong ayahs (surah 2 has 285 ayahs here
             and 286 in Kufi). The count fits `madani_first`, `madani_last`, `makki`, `dimashqi`.
             at exports/al-baqarah.json
             →  state the riwayah or the numbering
             basis: rule 072
```

الفكرة ببساطة: سورة البقرة ٢٨٥ آية في العد المدني، كما في رواية ورش، و٢٨٦ في العد الكوفي. والملف لا يذكر أي عدّ يتبع، فمن يقرؤه سيفترض العد الكوفي، كما تنص القاعدة ٠٧٢. وعندها يُربط كل توقيت بعد أول موضع يختلف فيه العدّان بآية غير آيته، والبيانات تُقرأ من غير أي خطأ ظاهر.

الحل سطر واحد في الملف نفسه:

```json
{
  "surah": 2,
  "riwayah": "warsh_an_nafi",
  "ayahs": [ … ]
}
```

بهذا السطر يعرف من يقرأ ملفك، من سجل القراءات، أن الأرقام بالعد المدني الأخير، من غير أن يسألك.

والفحص الثاني للأسماء. لنفترض أن لديك ملفًا اسمه `example.py`، تحفظ فيه رقم الآية ثم تطبعه:

```py
aya_number = 5
print(aya_number)
```

عند الـ commit، يتوقف الـ check ويعرض الملاحظتين التاليتين:

```text
example.py:1: error aya_number → ayah_number (rule 019: Ta marbutah outside idafah)
example.py:2: error aya_number → ayah_number (rule 019: Ta marbutah outside idafah)
```

كل سطر يوضح اسم الملف ورقم السطر، ثم الاسم الحالي والبديل المقترح والقاعدة. الملف نفسه لم يتغيّر: تصحح الاسم في السطرين، ثم تضيف التعديل باستخدام `git add example.py` وتعيد الـ commit.

## كيف أضيفها إلى مشروعي؟ [#set-up]

تحتاج إلى [أداة pre-commit](https://pre-commit.com/#install). بعد ذلك، أنشئ ملفًا باسم `.pre-commit-config.yaml` في المجلد الرئيسي للمشروع، وضع فيه:

```yaml
repos:
  - repo: https://github.com/marqoom-specs/quranic-terminology-lint
    rev: v0.5.0
    hooks:
      - id: quranic-data
      - id: quranic-terminology
```

وإذا كان الملف موجودًا عندك، أضف المستودع إلى قائمة `repos` الموجودة فيه. وفحص الأسماء اختياري: إذا كان يهمك فحص البيانات فقط، احذف السطر الأخير. ثم شغّل الأمر التالي من داخل المشروع:

```bash
pre-commit install
```

في المرة الأولى يبني pre-commit الأداة، وينزّل Rust بنفسه إذا لم يكن عندك، لذلك قد يأخذ ذلك بضع دقائق. ومن بعدها، ستعمل الـ checks عند كل commit على الملفات التي جهّزتها باستخدام `git add`. ولمراجعة ملفات المشروع الموجودة أصلًا:

```bash
pre-commit run --all-files
```

أنصح بالبدء بهذا الأمر وقراءة النتائج، خصوصًا في مشروع قديم. الخطأ يوقف الـ commit، أما التحذيرات والملاحظات فلا توقفه.

## ماذا لو لم أستطع تغيير الملف أو الاسم؟ [#exceptions]

أحيانًا لا تستطيع تعديل ملف البيانات، لأنه يصلك من مصدر آخر مثلًا. عندها اذكر روايته في ملف `.terminology.json` في المجلد الرئيسي للمشروع. وفي الملف نفسه تستثني أسماء تفرضها مكتبة خارجية، أو ملفات تريد الاحتفاظ بها كما وصلت إليك، وتكتب سبب كل استثناء:

```json
{
  "data": {
    "files": { "exports/al-baqarah.json": { "riwayah": "warsh_an_nafi" } }
  },
  "exclude": ["data/**"],
  "external_names": ["\\bChapters\\b"],
  "_comment": "Chapters is an export owned by our Quran API dependency."
}
```

لكن انتبه: إذا كان الملف يُنشر لمشاريع أخرى، فهي لا ترى هذا الإعداد. لذلك اكتب الرواية في الملف المنشور نفسه، كما في المثال الأول.

ولتجاوز سطر واحد، أضف إليه تعليقًا فيه `terminology: ignore`. وتسمح الأداة في التعليقات والشرح بأسماء مثل `Tajweed`، حتى لو كان المعيار يختار `tajwid` للمتغيرات.

## هل يمكنها تعديل الأسماء؟ [#unsafe-fix]

الإعداد السابق يشغّل check فقط: يقترح التصحيحات ويترك الملفات كما هي. وإذا أردت تطبيق التصحيحات تلقائيًا، استبدل `quranic-terminology` في الإعداد بـ `quranic-terminology-unsafe-fix`. عندها يصبح `example.py`:

```py
ayah_number = 5
print(ayah_number)
```

وسمّيناه unsafe لأن تغيير الاسم قد يؤثر في كود آخر. إذا كنت تستورد `Chapters` من مكتبة، فإن استبداله بـ `Surahs` قد يكسر الـ import؛ فالمكتبة ما زالت تستخدم الاسم القديم. لذلك راجع الـ diff وشغّل الـ tests بعد التعديل، ثم أعد الـ commit. وهذا للأسماء فقط: الأداة لا تعدّل ملفات البيانات أبدًا.

## أين أجد التفاصيل؟ [#more]

تجد التثبيت المباشر والتشغيل في CI، وكل ما يراجعه الفحصان، وتفاصيل الإعداد في [توثيق الأداة](https://github.com/marqoom-specs/quranic-terminology-lint/blob/v0.5.0/README.md). والقواعد نفسها مشروحة في [معيار التسمية](/ar/docs/terms/standard)، وأنظمة العد والقراءات في [السجلات](/ar/docs/terms/registries). والأداة مفتوحة المصدر برخصة MIT.

كل نموذج من النماذج الأربعة يسرد ما يجب أن يُعرف عن شيء واحد. ولكل معلومة [مستوى](/ar/docs/audio#levels): مطلوب أو متوقع أو اختياري.

## ١. القارئ [#reciter]

القارئ شخص واحد، يُذكر مرة واحدة مهما كثرت تسجيلاته.

| المعلومة | ما تفيده | المستوى |
| --- | --- | --- |
| الاسم بالعربية | الاسم بالحروف العربية. | مطلوب |
| الاسم بالإنجليزية | الاسم نفسه بالحروف اللاتينية. | متوقع |
| المصدر | كل مصدر يذكر القارئ، مع الاسم والمعرّف اللذين يعطيهما له، كما هما. فكل مصدر يكتب القارئ نفسه بطريقته. | متوقع |
| البلد | البلد الذي ينتمي إليه القارئ. | اختياري |
| سنة الميلاد | تميّز مع البلد بين قارئين متشابهَي الاسم. | اختياري |

[سجل القراء](/ar/docs/audio/registries#reciters) يعطي كل قارئ رمزًا واحدًا واسمًا واحدًا، حتى يقصد الجميع الشخص نفسه.

```json title="مثال: قارئ"
{
  "code": "maher-muaiqly",
  "name": { "ar": "ماهر المعيقلي", "en": "Maher Al Meaqli" },
  "sources": [
    { "name": "mp3quran", "id": "102", "labels": ["ماهر المعيقلي", "Maher Al Meaqli"] }
  ],
  "country": null,
  "birth_year": null
}
```

## ٢. تسجيل التلاوة [#recitation]

تسجيل التلاوة تسجيل واحد للقرآن أو لبعضه بصوت قارئ واحد، مثل تسجيل ماهر المعيقلي المرتل برواية حفص. وإذا سجّل القارئ نفسه رواية حفص مرتلةً مرة أخرى، فذلك تسجيل ثانٍ. وأي مدخلين في مصدرين يبقيان تسجيلين إلى أن يُعرف أنهما تسجيل واحد.

| المعلومة | ما تفيده | المستوى |
| --- | --- | --- |
| القارئ | من قرأه، ويُسمّى برمزه في [سجل القراء](/ar/docs/audio/registries#reciters). | مطلوب |
| القراءة والرواية | القراءة والرواية اللتان قُرئ بهما، مثل حفص عن عاصم. وتسجيل القراءة كاملةً يذكر روايتيها كلتيهما. | مطلوب |
| نمط الأداء | كيف قُرئ. واحد من ثلاثة: مرتل أو مجود أو معلم. ونمط الأداء ليس رواية. | مطلوب |
| المصدر | كل مصدر ينشره، مع الاسم والمعرّف اللذين يعطيهما له ذلك المصدر، كما هما. | مطلوب |
| التاريخ والمكان والمناسبة | متى سُجّل وأين، وفي أي مناسبة: استوديو أو صلاة أو تلاوة حية أو إذاعة. وهذا يميّز بين تسجيلين للقارئ نفسه. وتُذكر السنة مع تقويمها: هجري أو ميلادي. | متوقع |
| المنتج | الجهة أو المشروع الذي أنتج التسجيل. والمنتج ليس مصدرًا: المصدر ينشر التسجيل فقط. | متوقع |
| المالك والترخيص | من يملك التسجيل، وما يُسمح لغيره أن يفعل به. | متوقع |
| الطريق والوجه | الطريق الذي قُرئ به، مثل الشاطبية، والوجه: ما أخذ به القارئ حيث تجيز الرواية أكثر من وجه، مثل قصر المد المنفصل أو توسطه. والتسجيل الذي يجمع الأوجه كلها، أي الجمع، يذكر ذلك. وهذا يميّز بين تسجيلين بالرواية نفسها. | اختياري |
| مرتبة القراءة | سرعة القراءة: التحقيق أو التدوير أو الحدر. | اختياري |

ما يشمله التسجيل لا يُذكر مستقلًا، بل يُعرف من ملفاته الصوتية.

```json title="مثال: تسجيل تلاوة"
{
  "id": "maher-muaiqly/r1",
  "reciter": "maher-muaiqly",
  "qiraah": "asim",
  "riwayahs": ["hafs_an_asim"],
  "style": "murattal",
  "sources": [
    { "name": "mp3quran", "id": "102", "label": "حفص عن عاصم - مرتل" }
  ],
  "recorded": { "year": null, "place": null, "occasion": null },
  "producer": null,
  "owner": null,
  "license": null,
  "tariq": null,
  "wajh": null,
  "pace": null
}
```

في هذا التسجيل كل ما هو مطلوب في تسجيل التلاوة. أما تاريخه ومكانه ومناسبته ومنتجه ومالكه وترخيصه فغير معروفة، فيمكن استخدامه لكنه ناقص: لو وُجد تسجيل مرتل ثانٍ للقارئ نفسه لما أمكن تمييزه عن هذا، والمطور لا يعرف هل يُسمح له بمشاركته.

## ٣. الملف الصوتي [#audio-file]

الملف الصوتي ملف واحد بعينه: إذا تغيّر فيه أي شيء صار ملفًا صوتيًا آخر. ويصفه أمران: نطاقه، وهو ما يحويه، كسورة واحدة أو آية واحدة، وجودته، وهي صيغته ومعدل البت فيه. وقد يُنشر التسجيل نفسه بأكثر من نطاق وبأكثر من جودة، وكل ملف منها ملف صوتي مستقل.

| النطاق | ما يحويه الملف | مثال من مصدر |
| --- | --- | --- |
| القرآن | القرآن كاملًا في ملف واحد. |  |
| الجزء | جزء واحد. |  |
| السورة | سورة واحدة. | `001.mp3` في MP3Quran |
| الصفحة | صفحة واحدة من مصحف. | `Page001.mp3` في EveryAyah |
| الآية | آية واحدة. | `001001.mp3` في EveryAyah |
| الآيات المتتالية | أي آيات متتالية أخرى، من آية إلى آية. |  |

النطاق صفة للملف، وليس للتسجيل.

البصمة تميّز بين ملفين. وهي قيمة تُحسب من الملف، وتتغير إذا تغيّر فيه أي شيء. فالسورة ١ بصوت مشاري العفاسي في MP3Quran (٨٣٧٬٧٣٤ بايت) والسورة نفسها في QuranAPI (٨٣٩٬٥٣٠ بايت) لهما الصيغة نفسها ومعدل البت نفسه، لكن بصمتيهما مختلفتان: فهما ملفان.

| المعلومة | ما تفيده | المستوى |
| --- | --- | --- |
| تسجيل التلاوة | التسجيل الذي ينتمي إليه الملف. | مطلوب |
| النطاق | ما يحويه الملف، من القائمة أعلاه. | مطلوب |
| الرقم أو مفتاح الآية | أيّ واحد منها يحويه الملف. السورة والجزء والصفحة تُسمّى برقمها، والصفحة بطبعة مصحفها أيضًا. والآية تُسمّى بمفتاحها، مثل `2:255`، والآيات المتتالية بمفتاحَي أول آية وآخر آية فيها. ومفتاح الآية يذكر نظام عد الآي الذي يتبعه، لأن الآية نفسها قد يكون لها رقم آخر في رواية أخرى. | مطلوب |
| الصيغة | نوع الملف، مثل mp3 أو opus. | مطلوب |
| معدل البت | متوسط معدل البت للصوت وحده، بالكيلوبت في الثانية، مثل ١٢٨ أو ٦٤. ويُقاس من الملف، ولا يُؤخذ من اسم مجلد. | مطلوب |
| البصمة | تُحسب دائمًا بخوارزمية sha256. والملفان اللذان لهما البصمة نفسها ملف واحد. | مطلوب |
| مكان الملف | رابط واحد على الأقل يمكن تنزيل الملف منه. وقد يكون الملف نفسه على خوادم كثيرة، فالملف ليس هو الرابط. | مطلوب |
| المدة | مدة تشغيل الملف، وتُقاس بفك ترميزه. | متوقع |
| الحجم | حجم الملف بالبايت. | متوقع |
| معدل العينات والقنوات | عدد العينات في الثانية الواحدة، وهل الملف أحادي القناة أو ستيريو. وملف opus يُشغَّل دائمًا بمعدل ٤٨٬٠٠٠. | متوقع |
| المؤثرات | هل أُضيفت إلى التسجيل مؤثرات صوتية، كالصدى. وقد يُنشر التسجيل نفسه بها ومن غيرها. | متوقع |
| الأصل | إذا كان الملف مقتطعًا من ملف آخر، أو محوّلًا عنه، أو أُعيد وسمه فقط: أي ملف، وكيف. | متوقع |

```json title="مثال: ملف صوتي"
{
  "recitation": "maher-muaiqly/r1",
  "scope": "surah",
  "surah_number": 1,
  "format": "mp3",
  "bitrate_kbps": 64,
  "sha256": "3580f1114e2fe598b484402e7aa68abd15e22b8ec44be3396259e054bf1e839c",
  "urls": ["https://cdn.mp3quran.net/audio/maher-muaiqly/r1/001.mp3"],
  "duration_ms": 38060,
  "size_bytes": 330623,
  "sample_rate_hz": 22050,
  "channels": 2,
  "effects": null,
  "made_from": null
}
```

لا تُشترط صيغة معينة. وللتسجيل الجديد نوصي بهذه:

| الصيغة | الغرض منها |
| --- | --- |
| wav أو flac | الأصل. لا يضيع فيه شيء من التسجيل، وعليه تُعدّ توقيتاته. |
| m4a | النسخة التي تُنشر. تشغّلها كل الأجهزة تقريبًا. |
| opus | نسخة أصغر للتطبيقات. يبقى الصوت واضحًا بمعدل بت منخفض، لكن Safari لا يشغّلها إلا ابتداءً من iOS 18.4. |
| mp3 | نسخة للأجهزة القديمة فقط. وقد لا يكون توقيت الأصل دقيقًا عليها. |

## ٤. التوقيت الصوتي [#timing]

التوقيت الصوتي يحدد متى تُسمع كل آية أو كلمة داخل ملف صوتي واحد، ببداية ونهاية. ولا يلزم أن يكون للملف الصوتي توقيت. فإن كان له، وجب أن يُعرف الآتي:

| المعلومة | ما تفيده | المستوى |
| --- | --- | --- |
| الملف الصوتي | الملف الذي أُعدّ له التوقيت، ويُسمّى ببصمته. | مطلوب |
| الوحدة | ما الذي يوقَّت: الآية أو الكلمة. | مطلوب |
| العد | نظام عد الآي الذي تتبعه الأرقام، مثل العد الكوفي. وتوقيت الكلمات يذكر أيضًا النص الذي تتبعه مواضع كلماته. | مطلوب |
| المداخل | توقيتات الآيات أو توقيتات الكلمات فيه: كل آية أو كلمة يوقّتها، مع بدايتها ونهايتها محسوبتين من بداية الملف. | مطلوب |
| المُعِدّ والطريقة | من أعدّ التوقيت، وكيف: يدويًا أو بأداة. | متوقع |

```json title="مثال: توقيت صوتي"
{
  "audio_file": "3580f1114e2fe598b484402e7aa68abd15e22b8ec44be3396259e054bf1e839c",
  "unit": "ayah",
  "ayah_numbering_system": "kufi",
  "made_by": "mp3quran",
  "method": "tool",
  "entries": [
    { "ayah_key": "1:1", "start_ms": 1100, "end_ms": 4623 },
    { "ayah_key": "1:2", "start_ms": 4623, "end_ms": 8581 },
    { "ayah_key": "1:3", "start_ms": 8581, "end_ms": 11259 },
    { "ayah_key": "1:4", "start_ms": 11480, "end_ms": 13978 },
    { "ayah_key": "1:5", "start_ms": 13978, "end_ms": 18016 },
    { "ayah_key": "1:6", "start_ms": 18370, "end_ms": 20694 },
    { "ayah_key": "1:7", "start_ms": 20694, "end_ms": 34810 }
  ]
}
```

قد يحوي الملف صوتًا ليس آية: الاستعاذة، والبسملة قبل السورة، والصمت. فلا يلزم أن يبدأ المدخل حيث انتهى الذي قبله، ويمكن أن يذكر التوقيت مثل هذا الصوت في مدخل مستقل. وإذا كرر القارئ آية ظهرت مرة أخرى، بترتيب سماعها.

التوقيت يخص ملفًا واحدًا. لكنه يصلح أيضًا لكل ملف حُوّل عن ذلك الملف أو أُعيد وسمه فقط، ما لم يُقطع من الصوت شيء أو يُضف إليه شيء: فكل صوت يُسمع عندها في اللحظة نفسها في الملفين. ومعلومة «الأصل» في الملف تذكر ذلك. فتوقيت واحد يُعدّ على الأصل يصلح لكل نسخه، بكل معدلات البت. ولا يلزم نشر الأصل: بصمته تكفي لتسميته.

ضغط الصوت يضيف قبله حشوًا قصيرًا. وقد يسجّل الملف طول هذا الحشو، فيتخطاه المشغّل. وتُحسب الأوقات من حيث يبدأ المشغّل التشغيل، بعد الحشو الذي يتخطاه. وملف opus يسجّل حشوه دائمًا، وملف m4a يسجّله في العادة، فتوقيت الأصل دقيق عليهما. أما ملف mp3 فقد لا يسجّله، وعندها يُسمع كل صوت بعد الوقت الذي يذكره التوقيت: في اختبارنا تأخر الصوت ٢٥ ملّي ثانية في ملف فيه ٤٤٬١٠٠ عينة في الثانية، و٥٠ في ملف فيه ٢٢٬٠٥٠.

ملف السورة مع توقيت آياتها ليس كمجموعة من ملفات الآيات.
